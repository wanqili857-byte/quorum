# demo · 三个事故

**情节是真的，数据全是编的。** 三个事故都来自真实复核里抓到的、性质不同的静默错误。
共同点：**门禁是绿的，材料是错的**——绿灯为真，但它证明的不是读者以为的事。

三个审核员全部走**桩通道**（打印 `canned/` 里的预设结论），所以整个过程**零密钥、零网络**。

```bash
python3 project/make.py
quorum run    --config review.yaml --all
quorum plate  --config review.yaml --dispose
quorum verify --config review.yaml --ledger ledger_example.md
```

## 事故一 · 把覆盖率当成了准确率（`report.md` / `data/pred_old.jsonl`）

报告写「**严格命中 41.0%（held-out 100 条）**」。跑一下 `project/metrics.py`：

```
覆盖率（有预测的条数 / 全集）: 41/100 = 41.0%
准确率（在有预测的那些上）  : 31/41 = 75.6%
准确率（把缺的算错，对全集）: 31/100 = 31.0%
```

41.0% 是**覆盖率**，不是准确率。作者把前者写成了后者，而预测文件里缺的那 59 条
被静默当成「不存在」而不是「答错」。

**门禁为什么绿**：`gate.py` 检查的是「预测里的 id 是否都能在答案里找到」——
而这里的毛病是**缺**，不是多，所以它永远为真。**没有任何门禁在检查这两个数是不是同一个东西。**

## 事故二 · 门禁绿材料错（`report.md`）

数字区块完整且正确，但区块**之外**的正文一个字都没有——口径、方法、局限全不见了。

**门禁为什么绿**：它逐字节校验的是数字区块。正文不在它的管辖范围内，所以它永远有理由绿。

## 事故三 · 切分非确定性（`build.py`）

切分时遍历 `{r["id"] for r in rows}`（一个 `set`），字符串哈希每进程随机化——
**固定 `Random(42)` 也救不回来**，因为输入顺序本身就不固定。

```bash
PYTHONHASHSEED=0 python3 project/build.py
PYTHONHASHSEED=7 python3 project/build.py    # dev_ids 不一样
```

**门禁为什么绿**：`gate.py` 检查的是「预测里的 id 是否都能在答案里找到」——
而这里的毛病是**缺**，不是多，所以它永远为真。

## 还有一个「错的那一家」

`canned/gamma.md` 的那条 🔴 是**故意写错的**：它正确地观察到「报表用的是这份 41 条预测」，
却把归因写成「文件被人换掉了」。`quorum plate` 会把它和另外两家的正确结论对齐在同一簇，
并**在明细里逐条列出三家的原话**——你会看到同一处发现、三种措辞，其中一种是错的。

这就是为什么交叉表的「复验」列必须由人填：**审核员的结论是断言，不是事实。**
