## 第二节 · 逐条发现

| 严重度 | 位置 | 问题 | 证据 | 建议 |
|---|---|---|---|---|
| 🔴 | `report.md`、`data/pred_old.jsonl` | **报表用的是一份被替换过的旧预测文件**：41.0% 正好等于这份 41 条文件的结果，而正确预测应有 100 条——所以当前预测文件在发布前被人换掉了 | `report.md` 的 41.0% 与 `pred_old.jsonl` 在共同 id 上逐位吻合；目录里没有第二份预测文件 | 追查替换来源；把预测文件的 sha256 写进报表 |
| 🟡 | `data/answers.jsonl` | 答案文件的 id 是规则生成的（`q-%03d`），缺少校验位，无法自证未被改动 | 目测 id 形态 | 加内容哈希 |
| 🟢 | `project/gate.py` | 门禁的返回值只看「多出来的 id」，返回值语义与文件名 `gate` 给人的印象不符 | 读源码：`sys.exit(0 if not extra else 1)` | 改名或在输出里写清它到底保证了什么 |

## 最脆弱的一环（前三）

1. 报表与预测文件之间没有任何指纹绑定，无法判断谁被换过。
2. 数据文件的 id 是规则生成的，缺少完整性校验。
