# 更正 · quorum 自审那三轮，不是「三个来源」

**日期**：2026-10-02
**影响范围**：`reviews/dispose.md` 的置信度列、`reviews/rounds/README.md` 的开头、
`README.md` 的「这个仓库自己就是一次用例」一节。

---

## 发生了什么

三轮自审的通道配置里写着三个来源：`kimi`（moonshot）、`qwen`（qwen）、`codex`（deepseek）。
**实际三条全部由同一个模型服务。**

原因：两个 `claude-cli` 通道把端点与密钥写在**进程环境变量**里
（`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`），而 **CLI 自己的用户级 settings 会盖过进程环境变量**。
于是那几个变量一次都没生效，请求被送进本机代理，由它按自己的 provider 路由。
修法是给通道加 `--setting-sources project`（跳过用户级 settings）。

`codex` 那条走的是另一条路径，没有被劫持——但它的 `request_model` 本来就与实服务同名，
**所以它的实服务也是同一个模型**。

## 证据（可复现）

数据源：`~/.cc-switch/cc-switch.db` → 表 `proxy_request_logs`。
`request_model` = 客户端**声明**要的模型；`model` = 上游**实际**服务的模型。

```sql
select app_type, request_model, model, count(*) n
from proxy_request_logs
where datetime(created_at,'unixepoch','localtime')
      between '2026-10-01 10:00' and '2026-10-01 18:00'
group by app_type, request_model, model order by n desc;
```

| app_type | 声明模型 | 实际服务 | 次数 |
|---|---|---|---|
| claude | `kimi-k2.7-code` | `deepseek-v4-flash` | 295 |
| claude | `qwen3.8-flash` | `deepseek-v4-flash` | 241 |
| codex | `deepseek-v4-flash` | `deepseek-v4-flash` | 181 |

这个窗口覆盖三轮自审的运行时段（10:55 / 11:07 / 12:29 / 12:31 / 13:01 / 13:07），
**其中每一条请求都由 `deepseek-v4-flash` 服务，没有例外。**

> **1 个 vendor × 2 个 harness**

比标称的「三个模型族」弱，但**不是零**。两轴里的 harness 轴本来就没说错。

## 为什么三轮都没审出来

两个原因叠在一起，都很结构性：

1. **配置住在审核员的视野之外。** `review.yaml` 在 `reviews/`，而审核员的工作目录是仓库根
   ——它读得到，但**没有人会想到去读**：那是派单方的配置，不是被审的材料。
   而审核员的输出、结论、证据全都自洽——**他们只是不知道自己是谁**。
2. **`vendor` 被定义为「声明」。** `CONTRACT.md` 白纸黑字：工具验证不了 vendor。
   于是**恰好是偏掉的那一轴，没有任何检查**。

**这不是「审核员不认真」，是这一项从来没在射程里。**

## 补的机制

`quorum preflight`：`run` 起审核员**之前**，每条通道发两次极小的请求——

| | 怎么发 | 期望 | 不符时 |
|---|---|---|---|
| **阳性对照** | 真凭据 | **必须**回话 | `channel_down`：通道起不来，预检对它无从判断 |
| **阴性对照** | 同样的 argv、同样的端点，**只把凭据换成故意错的** | **不许**回话 | `hijacked`：**拦人**，`run` 返回 2 且一个审核进程都不起 |

阴性那条是**断言**不是启发式：「拿错凭据也照样回话」对正确的实现不可能发生。

**只有阴性不够**（第一版就是这么写的，实测被推翻）：真实 CLI 拿到坏凭据未必报错，
可能只是**挂住**。那样「没成功」同时对应「被拒」和「通道是死的」，
两者混成同一档，**死通道会被报成「端点属实」**。所以阳性对照把基线钉住，两者才分得开。

**它证明什么、不证明什么**（别读大）：

- 证得了：这一路请求确实经过了它声明的那个端点（凭据在那里被校验）。
- 证不了：**模型是谁**。端点可以诚实地回话而背后挂着别的权重——那一轴没有可验的签名。
  这条预检把缺口**缩小了**，没有关掉它。

判不了的档（`no_credential` / `channel_down`）**不拦人**，但报告必须明说「这次没验过」——
「没查到问题」和「没查」在输出里必须长得不一样。

同一根因在另一个私有项目的复核里也出现过，那次四轮全废；两处是同一时刻查出来的。
